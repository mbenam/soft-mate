# rt60 — the reverb decay rig

**Source:** [`tools/rt60_run.py`](../../tools/rt60_run.py),
[`tools/rt60_measure.py`](../../tools/rt60_measure.py),
[`tools/set_rev_decay.py`](../../tools/set_rev_decay.py) (Python 3, stdlib only).
**Build target:** none. They drive [`m8drv`](m8drv.md) and [`m8_capture`](m8_capture.md).
**Category:** measurement harness for the send-effect group.
**Findings:** [`hw_findings.md`](hw_findings.md) §UI-29.

Three scripts, one job: set the reverb `DECAY` byte, capture a tail that is
actually a tail, and get a decay time out of it that somebody else can check.

## `set_rev_decay.py <HEX>`

`m8drv set REV_DEC` **cannot do this**, and the reason is worth knowing before
you meet it on another paired field. EFFECT SETTINGS draws decay and shimmer as
one row —

```
       DECAY:SHIMMER C0:00
```

— and `readCursorValue` returns the accent-coloured cells glued together as
`:SHIMMERC0`, which has no leading hex run for `editValue` to converge against.
It refuses. **That refusal is correct**: one attempt to force it timed out
mid-sweep and left `DECAY` on `45`, an unasked-for value that the next capture
would have measured and believed.

This script reads the byte out of the decoded **row text**, which is unambiguous,
and steps it with the pinned `hw_buttons.json` gestures (`0x41` = +16, `0x21` =
−16, `0x05` = +1, `0x81` = −1), re-reading after every batch until it lands.
Same approach will work for `DEL_TIME_L:R` and `MOD DEPTH:FRQ`.

## `rt60_run.py`

One guarded capture. It is [`hw_measure`](hw_measure.md)'s before-and-after
discipline widened to three screens, because this measurement's meaning depends
on state that lives on INSTRUMENT (the instrument's sends), EFFECT SETTINGS (the
reverb block) and MIXER (the returns), and `hw_measure` reads INSTRUMENT only.

```powershell
python tools/rt60_run.py --out hwtest_out/rev/decC0.wav --dec C0 --seconds 18 `
    --note-ms 300 --vel 0x40 --expect "INSTRUMENT:REV FF" --expect "EFFECTS:ROOM SIZE     FF"
```

| Flag | Meaning |
|---|---|
| `--out <path>` | Output WAV. Required. |
| `--dec <hex>` | Step reverb `DECAY` here first, via `set_rev_decay.py`. |
| `--seconds` / `--note-ms` | Capture window, and how long the keyjazz note is held inside it. |
| `--vel` / `--keyjazz` | Velocity and MIDI note (defaults `0x40`, 60). |
| `--expect SCREEN:substring` | Assert this text is somewhere on that screen. Repeatable. |

| Exit | Meaning |
|---|---|
| 0 | Captured, and every decoded row on all three screens was identical afterwards. |
| 2 | The rig would not take, an `--expect` failed, or a row moved during the capture — the WAV is renamed `.DRIFTED`. |
| 3 | `m8_capture` failed. |

Drift is detected by comparing decoded **row text**, never the semantic-state
blob: `settled` flaps between reads whether or not anything moved
([`m8drv`](m8drv.md) Gotchas).

## `rt60_measure.py <wav> --note-ms <n>`

Reports three decay estimates rather than one, because they disagree and the
disagreement is information:

- **EDC −5→−65 dB** — Schroeder backward integration, crossing times off the
  energy-decay curve. Monotone by construction, so one quiet 10 ms bin cannot
  trip it. This is a **measured** 60 dB, not an extrapolation, and it is the
  column to quote.
- **T30 extrapolated** — the conventional −5 to −35 dB fit, ×2.
- **Envelope slope** — least squares on the raw 10 ms RMS envelope in dB. Runs
  high, because the first few hundred ms decay faster than the rest.

It also prints the EDC crossings at every 10 dB and the time of the last non-zero
sample.

## Gotchas

- **The M8's USB tap floors at exact digital zero**, not at a noise floor. That
  is what makes a real 60 dB measurement possible here, and it is why the last
  non-zero sample time is worth printing.
- **Backward integration against a truncated tail reports nonsense.** If the
  capture window ends while the reverb is still ringing, the EDC crossings bunch
  up against the end of the file and look like a fast decay. Check the last
  non-zero sample: if it is at the end of the file, the number is invalid.
  `DECAY FF` did exactly this in an 18 s window (§UI-29).
- **`--note-ms` is a `m8_capture` flag added for this.** Without it the keyjazz
  note is held for the whole recording, so the tail is never in the file.
